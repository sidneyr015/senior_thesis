Extending TRIE for Finding Invariants in Rust Crates

Sidney Richardson

Advised by Ramla Ijaz and Lin Zhong

Abstract

Large language models often struggle to preserve Rust’s implicit invariants when refactoring or transforming code, particularly those tied to ownership, lifetimes, and typestate behavior. These invariants are rarely written down explicitly; instead, they emerge from patterns involving generics, trait bounds, or ownership rules. As a result, automated systems frequently overlook constraints that are essential to maintaining program correctness. This project develops an initial three-stage pipeline that retrieves relevant code snippets, identifies potential state transitions and invariants, and validates them through a structured prompting and de-hallucination process. The pipeline begins with code summarization and selection, which uses keyword-based semantic search to locate snippets likely to encode typestate behavior. Next, an invariant-detection stage analyzes each snippet and constructs preliminary typestate entries capturing states, transitions, and supporting evidence. A final validation stage evaluates these entries for grounding, removes unsupported inferences, corrects entity names, and enforces that transitions align with actual function signatures. Applied to small Rust crates such as OnceCell, the system successfully produces typestate tables with explicit, line-level evidence, revealing both correct inferences and areas where LLMs tend to misinterpret or omit key constraints. Across iterative versions of the pipeline, improvements in retrieval, grounding, and validation yielded more consistent and interpretable results while exposing tradeoffs between recall and hallucination control. Although still exploratory, these findings suggest that structured retrieval and validation can help LLMs recover meaningful typestate information from real Rust code. The system provides a preliminary foundation for future tools aimed at supporting invariant-aware Rust-to-Rust transformations and guiding models toward more reliable reasoning about Rust programs.
